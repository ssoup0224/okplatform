**② 주제 소개 · 작품 개요 (0:50)**

> "저희 작품은 okchat 가드레일입니다. 한국어와 영어 챗봇에 들어오는 사용자 메시지를, 그 한 문장만이 아니라 **지금까지의 대화 전체 맥락 속에서** 평가해서 차단·안전응답·주의응답·허용 네 단계로 판정합니다.
> 정상 사용자의 오탐을 1% 이하로 묶어 두고 그 안에서 최대한 많이 잡는 것이 설계 목표입니다."

슬라이드: 한 장짜리 개요도 — `사용자 메시지 → [가드레일] → 4단계 판정 → 챗봇`.

**③ 개발 동기 · 기존 동향 (1:40)**

> "LLM 챗봇이 서비스에 들어가면서 '탈옥' 공격이 늘고 있습니다. 특히 위험한 건 **멀티턴 공격**입니다. 첫 질문은 평범하게 시작해서 몇 턴에 걸쳐 조금씩 유해한 요청으로 끌고 가는 방식인데, 한 문장씩만 보는 필터는 이를 놓칩니다.
> 여기에 한국어는 초성·자모 분리·신조어 같은 우회 표현이 많습니다.
> 기존 공개 가드 모델을 저희 테스트셋 10만 대화에 그대로 돌려 봤습니다. Meta의 Llama Guard 4는 유해 대화의 13.4%, 최신 Qwen3Guard-8B도 35.5%만 잡았고, **한국어만 보면 25.1%**였습니다. 대부분 영어 단일 턴 위주로 학습됐기 때문입니다."

슬라이드:
- 멀티턴 공격 예시 1개 (아래 '주의사항' 참고, 내용은 순화)
- 막대그래프: Llama Guard 4 13.4 / Qwen3Guard zero-shot 35.5 / (공란) 우리 시스템 → ⑤에서 채움
- 동향 키워드: Llama Guard, Qwen3Guard, WildGuard, 한국어 데이터(KOTOX, K-HATERS, AIHub) — 출처는 `REFERENCES.md`

**④ 주요 연구/개발 내용 (2:00)** — 기술 깊이를 보여주는 구간, 탁월성 40점

> "시스템은 네 부분으로 되어 있습니다.
> 첫째, **데이터**. 52개 공개·AIHub 데이터셋 56만여 건을 하나의 스키마로 통합했고, 부족한 한국어 멀티턴 공격은 7B 공격 생성 모델로 크레센도·분해·롤플레이 유형을 직접 만들고 번역·난독화로 늘렸습니다.
> 둘째, **가드 모델**. Qwen3Guard-Gen-8B를 4-bit QLoRA로 약 10만 8천 개 대화에 미세조정했습니다. RTX 4090 한 장에서 돌리기 위해 체크포인트 기반으로 여러 세션에 나눠 학습했습니다. 옆에서 KcELECTRA 혐오표현 분류기가 함께 돕니다.
> 셋째, **궤적 판정**. 각 턴의 위험 점수 흐름 — 최고점, 이동평균, 과거 차단 사례와의 유사도 — 를 LightGBM으로 묶어 대화 단위로 판정합니다.
> 넷째, **운영**. 오탐 1% 예산 안에서 언어별 임계값을 통계적 여유(Clopper–Pearson 95%)를 두고 정하고, 검토자 피드백은 재학습 없이 즉시 메모리에 반영됩니다. 새 버전은 기존 테스트셋 어디서도 나빠지지 않을 때만 배포됩니다."

슬라이드: 아키텍처 다이어그램을 4단계로 순서대로 강조 (데이터 → 가드 → 궤적 판정 → 운영 루프).
보조 슬라이드(시간 남으면): 평가 규모 — 테스트 101,229 대화 / 198,145 턴, 학습에 쓰지 않은 외부 평가셋 22종.

**⑤ 데모 (1:50)** — 완성도 40점의 핵심, **슬라이드 아님, 실제 동작 화면**

권장 구성 (각 30초 내외):
1. **정상 대화** — 평범한 질문 3턴 → 모두 `allow`, 위험 점수 낮게 유지
2. **멀티턴 공격** — 시나리오 ②. 1·2턴은 `허용`(점수 0.00), 3턴째에 0.82로 급상승해서 `안전 응답 + 검토`가 됩니다. 한국어 차단 임계값은 0.93이라 `차단`까지는 가지 않습니다. 이어서 시나리오 ②′로 **같은 3턴째 문장만 단독으로 보내면 0.27로 `허용`**되는 것을 보여 줍니다. "한 문장만 보는 필터는 통과시키는 공격을 대화 흐름으로 잡는다"는 것이 이 작품의 핵심이라 데모의 중심 장면입니다.
3. **한국어 우회 표현** — 초성/자모 분리 혐오 표현 → 탐지
4. (선택) **피드백 반영** — 놓친 사례를 검토자가 확인 → 재학습 없이 다음 요청부터 차단

각 시나리오 끝에 결과 숫자 슬라이드 1장:

| | 전체 탐지율 | 오탐률 | 한국어 탐지율 |
|---|---|---|---|
| Llama Guard 4 (zero-shot) | 13.4% | 0.74% | 9.1% |
| Qwen3Guard-8B (zero-shot) | 35.5% | 1.19% | 25.1% |
| **okchat (서빙 시스템)** | **60.9%** | **0.95%** | **55.0%** |

+ 응답 지연 p50 226 ms (RTX 4090) — "실시간 서비스에 붙일 수 있는 속도".

주의:
- **녹화 전에 실제 릴리스로 시나리오 5개를 모두 돌려 보세요.** 시나리오 문장은 예상으로 쓴 것이라 실제 모델 판정이 다를 수 있습니다. 결과가 기대와 다르면 `tools/demo/scenarios.json`의 문장을 고치되, **잘 잡히는 문장만 골라 결과를 꾸미지 말고** 놓치는 사례가 있으면 ⑥ 한계 구간에서 그대로 언급하세요.
- 서빙 시스템은 릴리스 설정(LightGBM 스택)을 따릅니다. 오프라인 분석이 권한 "가드 단독"으로 보여 주려면 `--decision-system guard`를 붙입니다. 발표에서 말하는 시스템과 화면 상단 `판정:` 표시가 일치하는지 확인하세요.
- `--backend mock`은 키워드 규칙일 뿐 모델이 아니며, 화면 상단에 빨간 `MOCK` 표시가 뜹니다. **mock 화면은 절대 녹화에 쓰지 마세요.**
- 자유 입력에 실제 챗봇 답변이 필요하면 vLLM 등으로 OpenAI 호환 서버를 띄우고 `--chat-api http://127.0.0.1:8000/v1 --chat-model <모델명>`을 붙입니다. 이때는 챗봇 답변 초안도 응답 검사(`assess_response`)를 거칩니다.

**⑥ 기대효과 · 향후 전망 (0:50)**

> "okchat 가드레일은 한국어 챗봇 서비스 앞단에 붙여, 정상 사용자 경험은 거의 해치지 않으면서 유해 대화의 84%에 차단·안전응답·주의응답 중 하나로 대응합니다. GPU 한 장으로 학습·운영이 가능해 중소 서비스도 쓸 수 있습니다.
> 한계도 분명합니다. 사람이 직접 만든 멀티턴 공격은 아직 40% 수준이고, 응답 검사 단계는 현재 설정에서 오히려 탐지율을 낮췄습니다. 앞으로 피드백 루프로 실제 공격을 계속 학습하고, 레드팀 자동화와 응답 검사 개선을 진행하겠습니다. 감사합니다."

→ 마지막 3초: 전원 컷 + 팀명/작품명/지도교수.

> 한계를 숨기지 않고 수치로 말하는 것은 심사에서 오히려 신뢰도를 높입니다. README의 "Stack vs guard decision", "Known limitations"이 근거입니다.

## 3. 외부 공개 시 주의사항 (두 영상 공통)

1. **유해 예시 원문을 그대로 보여주지 말 것.** 데모·UCC에 쓰는 공격 대화는 팀이 직접 만든 순화된 예시(예: "위험한 화학물질을 만드는 방법"류를 블러/말줄임 처리)를 사용합니다. 혐오 표현 예시도 일부 가림 처리.

4. `local_secrets.py`, `.env`, HF 토큰, AIHub 키가 화면 녹화에 찍히지 않게 주의 (터미널·에디터 탭 정리 후 녹화).
